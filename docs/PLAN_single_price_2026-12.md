# แผนพัฒนา: ราคาเดียว เรียนได้ N5–N1 (เริ่ม 1 ธ.ค. 2026)

สถานะ: **เขียนโค้ดและเทสแล้ว (25 พ.ย. 2026)** รอ deploy ขึ้น VPS (deploy ก่อนวันที่ 1 ได้ ราคาจะสลับเองตอนเที่ยงคืน)

สิ่งที่เพิ่มจากแผนเดิมตอนลงมือ:
- **ต่ออายุก่อนหมดแล้วไม่เสียวัน:** ใครมีสิทธิ์ระดับเดียวเหลืออยู่ แล้วซื้อแพ็กเกจทุกระดับก่อนหมดอายุ สิทธิ์ทุกระดับจะเริ่มนับต่อจากวันหมดอายุเดิม ไม่ได้เริ่มจากวันที่ซื้อ (`approve_payment`)
- **เทสเดิมที่เช็กราคาแบบเก่า (8 ตัว) ล็อกไว้ที่ "ช่วงราคาเดิม":** ใช้ `core.testing.LEGACY_PRICING` ไม่อย่างนั้นหลังวันที่ 1 เทสจะพังเอง
- **เทสชุดใหม่ 17 ตัวอยู่ใน `apps/payments/tests.py`:** รันทั้งชุดได้ 128 ตัว ผ่านครบทั้ง 3 แบบ คือ `SINGLE_PLAN_START` ค่าตั้งต้น, `2026-11-01` และ `2099-01-01`

## 1. สิ่งที่พี่ริวตัดสินใจแล้ว

| เรื่อง | ข้อสรุป |
|---|---|
| ราคา | รายเดือน 960 บาท (30 วัน), รายปี 9,600 บาท (365 วัน) เรียนได้ N5–N1 |
| แพ็กเกจอื่น | ปิด 6 เดือน และปิดตลอดชีพ |
| วันเริ่ม | 00:00 น. 1 ธ.ค. 2026 (เวลาไทย) **เปลี่ยนเองอัตโนมัติ** เดือน พ.ย. ขายราคาเดิม |
| Deploy | push แล้ว pull ขึ้น VPS ได้เลยก่อนวันที่ 1 ไม่ต้องทำอะไรในวันนั้น |
| นักเรียนเดิม | ใช้ระดับเดิมจนหมดอายุ ต่ออายุรอบหน้าจ่ายราคาใหม่ ได้ทุกระดับ |
| ราคาต่ออายุเฉพาะคน | เลิกใช้ ทุกคนจ่ายราคาใหม่เท่ากัน |
| วันแถมตอนต่ออายุ | ยกเลิก ต่ออายุได้ 30 วันพอดี (เดิมได้ 33) |
| Zoom | รวมอยู่ในราคา |
| ระบบสะสมยอดได้สิทธิ์ตลอดชีพ | **ไม่แตะ** ใครจ่ายเกิน พี่ริวคืนเงินเอง |
| สลิปราคาเดิมที่อนุมัติหลังวันที่ 1 | ได้สิทธิ์ตามที่ซื้อไว้ (ระบบทำอยู่แล้ว) |
| แจ้งนักเรียน | พี่ริวแจ้งเอง ไม่มีป้ายประกาศหรืออีเมลจากระบบ |

## 2. หลักการออกแบบ

- **ใช้คอร์ส N1 เป็นตัวแทน "ทุกระดับ":** ระบบสิทธิ์เดิม (`AccessService.video_rank_for` / `access_window`) ให้ระดับสูงครอบคลุมระดับล่างอยู่แล้ว ถ้ามีสิทธิ์ N1 ก็ดู N5–N1 ได้หมด จึง**ไม่ต้องแก้ตารางฐานข้อมูลและไม่มี migration**
- **สลับตามวันที่ในโค้ด:** ฟังก์ชัน `single_plan_active()` เช็ก `timezone.localdate() >= SINGLE_PLAN_START` ทุกจุดที่เกี่ยวกับราคาเรียกผ่านฟังก์ชันนี้ ก่อนวันที่ 1 ทำงานแบบเดิมทุกอย่าง
- **ราคาใหม่อยู่ใน settings ไม่แก้ราคาในฐานข้อมูล:** ราคาเดิมในตาราง `courses` ยังอยู่ครบ ถ้าต้องถอยกลับทำได้ทันที
- **ราคาต่ออายุเฉพาะคน "ไม่ใช้" แทน "ลบทิ้ง":** โค้ดจะไม่อ่านค่านี้หลังวันที่ 1 ข้อมูลในฐานข้อมูลยังอยู่ ไม่ต้องรันคำสั่งลบในวันนั้น
- **ตัวกันราคาเปลี่ยนกลางทางมีอยู่แล้ว:** ถ้าใครเปิดหน้าชำระเงินไว้ตอน 23:59 แล้วส่งหลังเที่ยงคืน `expected_amount` จะตอบ 409 "ราคามีการเปลี่ยนแปลง กรุณาเปิดหน้าใหม่"

## 3. รายการแก้ไข

### 3.1 ตั้งค่าและตรรกะราคา
- `config/settings/base.py`: เพิ่ม `SINGLE_PLAN_START` (ค่าตั้งต้น 2026-12-01 เปลี่ยนผ่าน .env ได้), `SINGLE_PLAN_MONTHLY = 960`, `SINGLE_PLAN_YEARLY = 9600`
- `apps/courses/pricing.py`:
  - `single_plan_active(today=None)`
  - `plan_course()` คืนคอร์ส N1 ที่ active (id ต่ำสุด)
  - `package_prices(course)` / `package_amount(course, days)` คืนแค่ 30 วันกับ 365 วันในราคาใหม่เมื่อเปิดใช้แล้ว
  - `renewal_days()` คืน 30 เมื่อเปิดใช้แล้ว ก่อนหน้านั้นคืน 30 + `RENEWAL_BONUS_DAYS`

### 3.2 จุดรับชำระเงิน (ฝั่งเซิร์ฟเวอร์)
- `apps/payments/services/payment_service.py` → `upload_slip_existing_user`: เมื่อเปิดใช้แล้ว
  - ไม่ว่าจะส่ง `course_id` อะไรมา ให้ใช้ `plan_course()` เสมอ
  - ไม่มีวันแถม (รับ 30 กับ 365 เท่านั้น ส่ง 33 มาให้ปฏิเสธพร้อมข้อความให้โหลดหน้าใหม่)
  - ไม่ใช้ `custom_renewal_price`
  - `level_access` บันทึกเป็น `"N5-N1"`
- `apps/users/services/auth_service.py` → `register_student`: เมื่อเปิดใช้แล้ว
  - ช่อง `level` ไม่บังคับแล้ว ใช้ `plan_course()` เสมอ
  - `is_zoom_included=True` (เดิมคนสมัครใหม่ได้ Zoom เฉพาะแพ็กเกจ 180 วันขึ้นไป)
- `approve_payment`: **ไม่แก้** ทำงานตาม `payment.course` ที่บันทึกไว้ สลิปเก่าเลยได้สิทธิ์ตามที่ซื้อไว้

### 3.3 หน้าต่างสมัครเรียนและชำระเงิน (`static/js/dialogs.js`, `templates/portal/_dialogs.html`)
- `course_selector.catalog()` และ boot payload เพิ่มข้อมูล `singlePlan` (เปิดใช้หรือยัง, ราคา, จำนวนวันต่ออายุ)
- หน้าต่างสมัครเรียน: ซ่อนช่องเลือกระดับ แสดงว่า "เรียนได้ทุกระดับ N5–N1" แทน ส่วนช่องระยะเวลามีแค่รายเดือนกับรายปี
- หน้าต่างชำระเงินหรือต่ออายุ: ซ่อนช่องเลือกคอร์ส และเปลี่ยนเลข `33` ที่ฝังไว้ตายตัว 2 จุด (บรรทัด 115, 127) ให้อ่านจาก `renewal_days`
- ลิงก์ `?auth=register&level=N3` เดิมยังใช้ได้ แค่จะไม่มีผลกับการเลือกระดับ

### 3.4 หน้าที่แสดงราคา
- `course_selector.price_table()` / `microsites/selectors/sales_selector.pricing()`: เมื่อเปิดใช้แล้วคืนข้อมูลแพ็กเกจเดียว ทำให้ข้อความ "เริ่มต้น ฿X/เดือน" บนไมโครไซต์เป็น 960 เองโดยอัตโนมัติ
- `templates/portal/salepage.html` (ส่วน `#pricing-section`) และ `templates/microsites/_price_table.html`: แสดงการ์ดเดียวแทนตาราง 5 แถว คือรายเดือน 960 กับรายปี 9,600 พร้อมบอกว่าประหยัด 1,920 บาท และเรียนได้ N5–N1 รวม Zoom ส่วนข้อความเรื่องสะสมยอดได้สิทธิ์ตลอดชีพยังคงไว้ เพราะระบบนี้ไม่ได้แตะ
- รูประดับบนหน้าขาย (ลิงก์ `?level=`) คงไว้เป็นภาพประกอบ ลิงก์ยังพาไปหน้าสมัครได้ตามปกติ
- `templates/portal/course.html` (บรรทัด 34): "฿960.- / 30 วัน · เรียนได้ทุกระดับ"
- `templates/portal/_welcome_window.html` (บรรทัด 56): ราคาบนการ์ดคอร์สทุกใบเป็น ฿960.-/ด
- `apps/portal/seo.py`: เปลี่ยนจาก AggregateOffer 0–50,000 เป็น offer 960 กับ 9,600 และแก้ข้อความ FAQ เรื่องราคา (ยังพูดถึงเรื่องสะสมยอดเหมือนเดิม) รวมถึงตรวจ seo ของไมโครไซต์ด้วย

### 3.5 ข้อความแจ้งเตือนและหลังบ้าน
- `apps/payments/tasks.py` (บรรทัด 115, Telegram): ถ้า `level_access == "N5-N1"` แสดงว่า "ทุกระดับ (N5–N1)"
- `templates/emails/renewal_reminder.txt` / `.html`: แก้ "รับสิทธิ์เพิ่ม 33 วัน" ให้ใช้ `renewal_days()`
- `templates/backoffice/courses.html`: ติดหมายเหตุว่าตั้งแต่ 1 ธ.ค. ราคาขายมาจากแพ็กเกจเดียว ช่องราคาของแต่ละคอร์สไม่มีผลกับหน้าขายแล้ว
- `templates/backoffice/users.html`: ติดหมายเหตุที่ช่องราคาต่ออายุเฉพาะคนว่าไม่ใช้แล้วตั้งแต่ 1 ธ.ค.

### 3.6 สิ่งที่ไม่แตะ
- `AccessService.LIFETIME_THRESHOLDS` และ `recalculate_lifetime_unlocks` (ระบบสะสมยอด)
- สิทธิ์ของนักเรียนเดิมทุกคน, สลิปที่ค้างอนุมัติ, ระบบ EasySlip
- Stripe (พักไว้)

## 4. การทดสอบ

**เทสอัตโนมัติ** (ไฟล์ใหม่ `apps/payments/tests.py` ใช้ `override_settings(SINGLE_PLAN_START=...)` สลับวันที่ ก่อนและหลังวันเปลี่ยน):
1. ก่อนวันที่ 1: ซื้อ N3 ได้ราคาเดิมของ N3 ต่ออายุได้ 33 วัน ใช้ราคาเฉพาะคนได้ (ต้องเหมือนเดิมทุกอย่าง)
2. หลังวันที่ 1: ส่ง `course_id` ของ N5 มา ต้องได้คอร์ส N1 ราคา 960, ส่ง 365 วัน ต้องได้ 9,600 และส่ง 180 หรือ 9999 ต้องถูกปฏิเสธ
3. หลังวันที่ 1: ต่ออายุได้ 30 วัน ไม่ใช้ราคาเฉพาะคน และส่ง 33 มาต้องถูกปฏิเสธ
4. หลังวันที่ 1: สมัครใหม่โดยเลือก N3 ต้องได้คอร์ส N1 และได้ Zoom
5. อนุมัติแล้วต้องเปิดบทเรียนของ N5 ได้ (ทุกระดับ)
6. สลิปราคาเดิมที่สร้างก่อนวันที่ 1 แต่อนุมัติหลังวันที่ 1 ต้องได้สิทธิ์ตามคอร์สเดิม
7. เปิดหน้าชำระเงินไว้ด้วยราคาเดิม แล้วส่งหลังเที่ยงคืน ต้องได้ 409
8. หน้าขายและไมโครไซต์แสดง 960 / 9,600 และไม่มีคอลัมน์ 6 เดือนกับตลอดชีพ
9. รันเทสเดิมทั้งชุด (ตอนนี้มี 111 เทส) ต้องผ่านหมด

**เช็กด้วยตาในเครื่อง:** รัน dev server 2 รอบ คือ `SINGLE_PLAN_START=2099-01-01` (ดูว่าเหมือนเดิมไหม) กับ `SINGLE_PLAN_START=2026-11-01` (ดูหน้าตาแบบใหม่) แล้วเปิดดูหน้าขาย หน้าคอร์ส หน้าต่างสมัคร หน้าต่างต่ออายุ และไมโครไซต์ ทั้งบนคอมและมือถือ

## 5. Deploy

1. commit แล้ว push ขึ้น main
2. บน VPS: `git pull` ตามด้วย `collectstatic` (เพราะ `dialogs.js` เปลี่ยน) แล้ว `systemctl restart ryu-web ryu-worker ryu-beat` ส่วน migration ไม่มี ผมจะเขียนคำสั่งให้ทีละบรรทัดตอน deploy
3. หลัง deploy เปิดเว็บดู ต้องยังเป็น**ราคาเดิม**
4. เช็กว่า Cloudflare ไม่ได้ cache หน้า HTML ไว้: `curl -sI https://www.ryusosense.online/ | grep -i cf-cache-status` ต้องได้ `DYNAMIC` หรือไม่มีบรรทัดนี้
5. เช้าวันที่ 1 ธ.ค.: เปิดเว็บดูว่าเป็น 960 / 9,600 แล้ว

**ถอยกลับ (ถ้ามีปัญหา):** ใส่ `SINGLE_PLAN_START=2099-01-01` ใน `.env` บน VPS แล้ว restart ระบบจะกลับเป็นราคาเดิมทันที โดยไม่ต้องย้อนโค้ด

## 6. งานเก็บกวาดหลังวันที่ 1 (ทำทีหลัง ไม่ด่วน)
- พอราคาใหม่ใช้งานได้นิ่งแล้ว ลบโค้ดฝั่ง "ก่อนวันที่ 1" ออก แล้วย้ายราคาแพ็กเกจไปเก็บในฐานข้อมูล ให้แอดมินแก้ราคาเองได้จากหลังบ้าน
- ถ้าวันหลังทำ Stripe ให้ใช้ `plan_course()` กับ `package_amount()` ชุดเดียวกันนี้
